# Как тестить titi руками

Точка входа для ручного тестирования. Собирай, запускай, гоняй чек-лист ниже.
Нашёл баг — см. «Как репортить».

## Сборка и запуск

```bash
cd ~/proj/titi

# собрать всё + прогнать все тесты (578 шт):
cargo test --workspace

# собрать бинарник без тестов:
cargo build -p titi-cli

# запустить TUI (обычный терминал):
./target/debug/titi

# запуск с поддержкой мыши (drag-select):
./target/debug/titi --mouse buttons
# пресеты: off | wheel | buttons | all
```

> macOS-first: тестируем в родном Terminal.app или Warp. tmux/iTerm — можно,
> но mouse-пресеты там ведут себя иначе (см. `docs/research/agent-ux/mouse.md`).

## Чек-лист

### 1. Адаптация к размеру терминала (свежий фикс)
- [ ] Терминал узкий (~60 колонок) → статус-линия тянется ровно на ширину окна
- [ ] Терминал широкий (~160 колонок) → то же самое, ничего не «плавает» слева
- [ ] Ресайз окна во время работы (мышью тянуть границу) → кадр перерисовывается,
      не остаётся «хвостов» старых строк
- [ ] Терминал очень узкий (~30 колонок) → ничего не ломается, строка усекается

### 2. Первый кадр
- [ ] Сразу после запуска виден баннер `titi v…` + статус `starting`
- [ ] Ввод в это время принимается, после готовности уходит провайдеру
      (в stderr будет `queued (provider starting): …` → `flushed after ready: …`)

### 3. Статус-линия
- [ ] `starting` → `ready` после инициализации
- [ ] После отправки промпта: `thinking`/`run` + таймер `⏱` + busy-индикатор
- [ ] Бейджи: `/details status expanded` — показывает секции; при бейджах
      (компрессии/фоновые/YOLO) строка расширяется, но не прыгает по ширине

### 4. Mouse (запуск с `--mouse buttons` или `all`)
- [ ] Drag-select мышью по тексту — выделение подсвечивается фоном
- [ ] Клик без drag — выделение снимается
- [ ] `/mouse off` — выделение отключается, работает нативное выделение терминала
- [ ] `/mouse all` — снова включается; пресет сохраняется (перезапуск — тот же)

### 5. Bracketed paste
- [ ] Вставь (Cmd+V) многострочный текст — вставляется одним блоком,
      команды по строкам НЕ выполняются
- [ ] Вставь >6 строк — сворачивается: `первая строка… (+N lines)`
- [ ] Вставь путь к картинке (`/tmp/foo.png`) — превращается в `[Image #1]`

### 6. Overlay-панели
- [ ] `Ctrl+X` — session switcher: ↑/↓, Enter — переключить, `Ctrl+D` — закрыть
      сессию (спросит подтверждение: Enter — да, Esc — нет), `Ctrl+N` — новая,
      `Ctrl+R` — обновить список, Esc — отмена (ничего не удаляет)
- [ ] `/model` — пикер моделей: ↑/↓ + Enter, Esc — отмена
- [ ] Esc всегда отменяет без побочных эффектов

### 7. Slash-команды и детали
- [ ] `/details <section> <mode>` — думать/инструменты/субагенты: expanded,
      collapsed, hidden
- [ ] `/details status expanded` — показывает статус-секцию

### 8. Выход
- [ ] `Ctrl+C` — чистый выход: экран восстанавливается, курсор виден,
      мышь отключена, bracketed paste выключен

## Как репортить

Пиши в чат в свободной форме + по возможности:
1. **Команду запуска** (например `./target/debug/titi --mouse all`)
2. **Терминал и размер окна** (Terminal.app/Warp, ширина в колонках)
3. **Последовательность действий** — что нажал/сделал перед багом
4. **Что ожидал vs что увидел**
5. Если можно — скриншот или `script -q /tmp/out ./target/debug/titi` + файл

Репорт уходит в работу как есть — не нужно ничего оформлять по шаблону.
