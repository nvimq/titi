# CONVEYOR — runbook цикла задачи

Каждая задача проходит один и тот же цикл. Стейт — `docs/research/STATE.md` (позже `docs/STATE.md` для реализации): единственная точка возобновления в новой сессии.

## Цикл задачи

1. **Взять** — из STATE.md задачу со статусом `todo`, перевести в `in-progress` (сразу, до работы).
2. **Детальный ресерч** — доки темы (README + deep-dive), при нехватке — точечное чтение первоисточников. Один раз; не переисследовать.
3. **Описание** — что делаем: контракты (типы/трейты), инварианты, список проверок. Зафиксировать в доке темы или PR-описании.
4. **Тесты** — сначала поведенческие тесты на контракт: границы, переходы, реальные ошибки. Тест падает → есть цель.
5. **Реализация** — минимальный код до зелёных тестов; без подавления симптомов.
6. **Верификация** — запушить сфокусированные коммиты; гейт истины — CI на GitHub-раннерах (fmt/clippy/test из `.github/workflows/ci.yml`). Локальный `cargo` необязателен и не рекомендуется (тяжёлый на машине); ничего не должно компилироваться локально.
7. **Консультация** — если тема вне личной экспертизы (UX-практики, терминальные нюансы, безопасность): параллельный вопрос эксперт-агенту через hub, пока идут другие задачи. Решение и источник зафиксировать в доке.
8. **Фиксация** — код + обновлённые доки + STATE.md → `done` (или `review` с вопросом). Коммит.

Правило остановки: 3 неудачные попытки на артефакт → эскалация к пользователю с описанием попыток.

## Автономная графовая разработка — практики

- **DAG, не список.** Задачи = узлы с зависимостями из research/README.md; порядок = топологический. Барьер только на реальной зависимости.
- **Параллелизация независимых тем.** Независимые поддеревья графа выполняются одновременно (веер подагентов); общий файл = общий владелец, остальные координируются через hub.
- **Изоляция владения.** У каждого параллельного узла свой файл/крейт; кросс-правки только через владельца или барьер слияния.
- **Контракты вперёд.** Интерфейсы между подсистемами фиксируются до параллельной реализации (в доках тем, секция Rust-маппинг) — иначе параллельные ветки не сойдутся.
- **Fail-isolated.** Падение одного узла деградирует только его поддерево; повтор через 3-попытки-правило.
- **Стейт после каждого шага.** STATE.md обновляется атомарно при смене статуса, не в конце дня — чтобы краш-сессия не теряла работу.
- **Переиспользование ресерча.** Тема исследуется один раз; результат — в доке; следующие задачи ссылаются на док, не на новые поиски.

## Цепочка воркеров графового цикла

Каждый узел DAG исполняется конвейером из четырёх ролей (паттерн orchestrator-worker, по практикам Anthropic multi-agent + локальная адаптация):

| Роль | Кто | Что делает |
|------|-----|------------|
| **Scout** | read-only агент (быстрая модель) | карта затрагиваемого кода/спеки узла; занимает минуты |
| **Worker** | свежий task-агент, 1–4 параллельно | тесты → реализация → cargo test своего крейта |
| **Reviewer** | reviewer-агент | ревью против DoD темы; ревью выявляет границы/инварианты |
| **Integrator** | главный агент | слияние в граф, кросс-крейтовая сборка, смоук, STATE.md |

Правила цикла (из production-уроков Anthropic):
1. **Делегирование без двусмысленности**: воркер получает цель, формат результата, границы файлов и список источников — расплывчатые задачи дублируют работу.
2. **Масштабирование усилий**: 1 воркер для простого узла, 2–4 для среднего; кап волны ~6 — «50 сабагентов» = спираль.
3. **Файлы, а не чат**: артефакты воркеров — в файлах (крейты, доки, local://), в сообщениях только лёгкие ссылки — защита от «испорченного телефона».
4. **Свежий контекст**: воркер начинает пустым, континуитет — через STATE.md и theme-доки, не через историю.
5. **End-state оценка**: проверяется конечное состояние (DoD + cargo test + смоук), не процесс.
6. **Состояние и ошибки копятся**: прогресс фиксируется в STATE.md после каждого шага; узел возобновляется с чекпоинта, не с нуля; 3 попытки → эскалация.
7. **Параллель независимостей**: узлы без общих файлов идут одновременно; общая точка (Cargo.toml workspace) — только через интегратора.
